Business behavior
  Import mode is STAGE. One MIR, rather than one passenger, is a staging record.
  Import does not write Sales, vouchers, ledgers or postings.
  MIR date comes exclusively from T50DTE. T50DFT has a separate date column.
  Invalid T50DTE leaves the date NULL and records a validation error, with no
  fallback to travel date, file time or import time. DDMMMYY normalization uses
  Go's explicit year pivot: 00-68 => 2000-2068; 69-99 => 1969-1999.
  Original bytes are durable in MySQL, including unsupported and failed records.
  Generic sections/items/fields retain evidence alongside 19 business child tables.
  Passenger/fare/segment joins use explicit guide references and ignore ambiguous
  competing targets. PNR passenger identities are not invented from item order.
  Multiple fares remain separate; the list leaves its fare summary blank when
  there is more than one A07 fare. No monetary aggregation or conversion is inferred.

Database migration and persistence
  Added version 0006_mir_staging.sql: 27 additive InnoDB tables with primary,
  unique and foreign keys; MIR-date/status/locator/source/batch/search indexes.
  Original source BLOB and SHA-256 have a unique source checksum. Each record's
  parent, generic fields, typed children and explicit relationships insert in one
  transaction. Reprocess locks the parent and replaces all children atomically.
  Failed replacement restores previous children. An interrupted source with no
  completed record can resume on retry without duplicating its source file.
  A separate durable record-error table captures transaction failures.
